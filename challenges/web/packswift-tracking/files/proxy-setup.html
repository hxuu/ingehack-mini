Request tool setup

PackSwift IT · for new starters · five minutes

Some support work needs us to look at the exact text a browser sends to one of our sites, and to send that text again with a small change. A browser will not show you that text. The request tool sits between the browser and the site and records it.

Use either tool below. Both are free and both do the same four things. Pick one and finish the whole page; you do not need the other.

ABurp Suite Community

  1. Download Burp Suite Community from portswigger.net/burp/communitydownload and run the installer. Accept the default options. Community is enough; do not buy anything.
  2. Open Burp. On the first screen choose Temporary project and then Use Burp defaults. The window that follows is the workbench.
  3. Open the Proxy tab, then Intercept. Check that Intercept is on is not blocking everything yet; we turn it on in step 5.
  4. In the same Proxy tab open Options (or Settings, depending on version) and find the proxy listener. It should say 127.0.0.1:8080. If it is off, turn it on.
  5. In your browser, set the HTTP proxy to 127.0.0.1 port 8080, and make sure localhost and 127.0.0.1 are not bypassed if the browser offers that setting. Reload any page. A request should now wait in the Intercept tab.
  6. Open the tool's own certificate page at http://burp in the same browser and follow the install link, so the browser trusts the tool. On Firefox this is enough; on Chrome import the certificate into the system store.

BCaido

  1. Download Caido from caido.io/download and run the installer. The free plan is enough.
  2. Start Caido and create a local project. Open the project.
  3. Open Settings, then Network, and note the proxy address, usually 127.0.0.1:8080. Start the proxy if it is stopped.
  4. Open Settings, then Certificate, and install the certificate in the browser you will use, following the on-screen instructions.
  5. Set the browser's HTTP proxy to 127.0.0.1 port 8080, and keep localhost and 127.0.0.1 out of the bypass list if the browser offers one.
  6. Open HTTP History and reload any page. The request should appear in the list.

THE FOUR THINGS YOU WILL DO

01

Scope

Tell the tool which host belongs to work. In Burp, right click the host in HTTP history and choose Add to scope. In Caido, right click the request and choose Add to scope. Everything else is background noise and can be ignored.

02

Intercept

Turn interception on, then load the page you are working on. The request pauses before it leaves. Read the first line and the headers: they are plain text, one per line.

03

Edit

Change the part you came to change. Keep the line endings as they are; the page reads them literally.

04

Send it again

To resend, in Burp press Forward to send the request you are holding, or right click it in HTTP history and choose Send to Repeater, then press Send in Repeater. In Caido use Replay and press Send. The response appears beside the request.

If no request appears: check that the browser proxy is 127.0.0.1:8080, that the tool's proxy listener is running on the same port, and that the site's address is not in the browser's bypass list. Turn the proxy off again when you are done with work.

New starters: post in the IT channel with the page you are on and the step number. Do not paste request contents into the channel.
